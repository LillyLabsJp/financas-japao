# START — como começar uma conversa nova

Documento curto. Serve para abrir uma conversa nova já com o contexto certo.

---

## 1. Documentos obrigatórios

Leia, nesta ordem:

1. `docs/ai-handover/HANDOVER-SONNET.md` — estado técnico e operacional
2. `docs/ai-handover/COMO-TRABALHAR-COM-LILLY.md` — preferências de colaboração

`docs/ai-handover/ROADMAP-E-IDEIAS.md` só precisa ser lido quando a tarefa
envolver planejamento, prioridades, páginas novas, projetos futuros,
brainstorming ou decisão estratégica.

Para tarefa mecânica, não é preciso reler o roadmap.

---

## 2. Confirmação inicial

Antes da primeira tarefa, confirme:

- repositório: `https://github.com/LillyLabsJp/financas-japao`
- branch: `main`
- último commit conhecido: `37a1949`
- estado do Git (`git status --porcelain`)
- site publicado abrindo: `https://financasnojapao.com/`
- quais acessos estão disponíveis nesta sessão
- fluxo de publicação: editar → GitHub Desktop → Commit to main → Push origin → esperar 1–3 min → conferir a URL

---

## 3. Papel do Sonnet

Executor técnico padrão do projeto: GitHub, edição de HTML, CSS e JavaScript,
instalação e conversão de imagens, testes de responsividade, commits, push,
acompanhamento do deploy e verificação do site publicado.

Decisão de estratégia, redesenho amplo e conteúdo fiscal continuam precisando de
autorização.

---

## 4. Prompt inicial pronto

Copie o bloco abaixo na primeira mensagem da conversa nova.

---

> Leia integralmente:
>
> 1. `docs/ai-handover/HANDOVER-SONNET.md`
> 2. `docs/ai-handover/COMO-TRABALHAR-COM-LILLY.md`
>
> Eles são a fonte operacional deste projeto.
>
> Consulte `docs/ai-handover/ROADMAP-E-IDEIAS.md` somente quando a tarefa envolver planejamento, ideias futuras ou estratégia.
>
> Antes de executar qualquer tarefa, confirme:
>
> - repositório: `https://github.com/LillyLabsJp/financas-japao`
> - branch: `main`
> - último commit
> - estado do Git
> - site publicado: `https://financasnojapao.com/`
> - acessos disponíveis
> - fluxo de deploy
>
> A partir desta conversa, assuma a execução técnica do projeto: GitHub, edição, testes, commits, push, publicação e verificação.
>
> Preserve as decisões congeladas listadas na seção 13 do handover.
>
> Não modifique arquitetura, design aprovado, conteúdo fiscal, domínio ou hospedagem sem autorização.
>
> Antes de cada tarefa, informe em no máximo cinco linhas:
>
> - o que entendeu;
> - quais arquivos pretende alterar;
> - qual resultado será produzido;
> - se existe algum risco real.
>
> Depois execute, teste, publique e informe:
>
> - arquivos criados;
> - arquivos modificados;
> - commit;
> - branch;
> - URL publicada;
> - testes realizados;
> - pendências reais.
>
> Não dependa da conversa antiga.
>
> Não peça novamente informações que possam ser verificadas no repositório, no site ou nos documentos.
